# AI sprite generation

Character sprites are generated by an image model, locked to fixed poses, then reduced to clean pixel art.
Two backends share the same poses, pixelize step, cache and review output:

- `--backend gemini` (Google, default model `gemini-3.1-flash-lite-image`, needs `GEMINI_API_KEY` in the
  git-ignored `.env` and billing enabled on the Google project; the free tier has no quota for image models).
  Each request sends the pose-guide sheet, a crop of the style reference (`refs/style_reference.jpg`,
  git-ignored), and prose instructions with a description of every cell.
- `--backend bedrock` (Stability Control Structure on Amazon Bedrock, us-west-2, `bedrock` AWS profile).

Every paid request goes through a budget guard (see `docs/ART_2X_PLAN.md`, hard rule 1):
- `--backend` is required.
- Uncached requests need `--paid`, and at most `--max-paid` (default 1) are allowed per run.
- Each paid attempt is written to `cache/ledger.jsonl` before the call; failures count as spent.
- Any earlier attempt at the same character+sheet blocks a new paid call unless `--retry` is passed.

```bash
python3 -I assets-src/gen/selftest.py                                                    # offline checks
python3 -I assets-src/gen/generate.py knight --backend gemini --sheets battle --seeds 1234 --dry-run
python3 -I assets-src/gen/generate.py knight --backend gemini --sheets battle --seeds 1234 --paid
python3 -I assets-src/gen/generate.py --repixelize assets-src/gen/out/gemini/knight/1234   # offline
```

Outputs go to `assets-src/gen/out/<backend>/<id>/<seed>/` (git-ignored): `<sheet>_guide.png`,
`<sheet>_raw.png`, `<sheet>_prompt.txt` / `_inputN.png` (dry run), `<sheet>.png` (native pixel sheet) and
`review.png`. Responses are cached in `cache/` by request hash.

**What is committed:** per character, `approved/<id>/{battle,field}.png` (the cut native sheets) and their `.json`
(cache key, flips, `head_from` fixes), plus the matching `cache/<key>.{png,json}` (the raw Gemini render, kept so
sheets can be re-cut offline and the self-test can prove each approved request still reproduces its key) and
`cache/ledger.jsonl`. Everything else (`out/`, rejected attempts in `cache/`) is local scratch. Store a reviewed
sheet with `python3 -I assets-src/gen/approve.py <id> <battle|field> [--flip left] [--flip-frames left:0]`.
`approved/knight/field_down.png` stays because the knight's approved field request used it as an identity input.

## Pipeline

1. **Spec** (`spec.py`) holds everything shared by all characters: the style prompt, negatives, grid sizes and the
   exact joint positions of every pose (32x40 pose units, feet on y=37).
2. **Guides** (`guides.py`) draw each pose as a grey mannequin. Far limbs are light, near limbs dark, and the head
   has a face-direction cue. All poses for a sheet go on one image, so the model draws one consistent character.
3. **Generate** (`bedrock.py`) calls Stable Image Control Structure with the guide, the shared style prompt, the
   character prompt from `characters.yaml` and a fixed seed.
4. **Pixelize** (`pixelize.py`):
   - Flood-fill keys out the background, and blobs that don't overlap the guide (invented props) are dropped.
   - A palette is k-means fitted on the full-resolution figure and snapped to 15-bit colour.
   - Each output pixel takes the most common palette colour in its block, with near-black ink taking priority.
   - Speckles are majority-filtered and a 1px outline is added.

## Sheets (1 art px = 2 screen px)

| Sheet | Layout | Frames | Native cell | On screen |
|---|---|---|---|---|
| `battle` | 3x2, 1536x1024 (3:2) | ready, attack, cast, hurt, down, victory (facing left) | 64x64, feet on row 61 | 128x128 |
| `field_down` | 3x1 strip, 768x512 (3:2) | stand, step L, step R, facing the viewer | 24x48, feet on row 46 | 48x96 |
| `field_up` | 3x1 | same, seen from behind | 24x48 | 48x96 |
| `field_left` | 3x1 | same, side view facing left (right = mirror) | 24x48 | 48x96 |

Gemini requests send: the pose guide, a crop of `refs/style_reference.jpg`, and (optionally) `identity_ref` from
`characters.yaml` upscaled 8x. Backgrounds are requested as solid magenta and keyed by colour; older white
renders fall back to a border flood fill.

## Adding a character

Add an entry to `characters.yaml` with `prompt` (costume only), `battle_gear`, `field_gear` and `seeds`. Generate,
review `review.png`, and move the approved seed to the front of `seeds`.

## Monster rig body templates (docs/ENEMY_ANIM_PLAN.md 4.1)

A rig file `anim/monsters/<sprite>.yaml` picks `body: biped | quadruped | bird`. The biped template is in `rig.py`; the
beast templates (T5a) are in `rig_templates.py`, whose docstring is the reference for the joint names. In short
(`_n` = near side, `_f` = far side, image coordinates, facing right):

| Body | Spine / head | Tail | Limbs | Wings (only when marked) |
|------|--------------|------|-------|--------------------------|
| `quadruped` (wolf, gr_wolf, dragon) | `hip` (root) → `back` → `chest` (`body` chain) → `neck` → `head` (`neck` chain) → `snout` (`head` rigid) | `tail0` → `tail1` → `tail2` → `tail_tip` (`tail` chain) | fore `sh` → `el` → `paw` → `ftoe`; hind `hip_n/f` → `knee` → `foot` → `toe` | `wsh` → `wel` → `wtip` from `chest` |
| `bird` (cockatrice) | `hip` (root) → `chest` (`body` torso) → `neck` → `head` (`neck` chain) → `beak` | same `tail` chain (the snake tail) | `hip_n/f` → `knee` → `foot` → `toe` | `wsh` → `wel` → `wtip` from `chest` |

- Chain parts (`body`, `neck`, `tail`) are mesh-warped with `width: auto`, so the warp covers every pixel the part
  segments to; override `chain` for more joints (e.g. a longer snake tail) and add parts such as a jaw
  (`parts: {jaw: {bone: [head, jaw]}}`) as usual.
- Pins: wind-up and recover pin every knee / elbow and foot / paw; follow, hurt and cast pin every foot (four on a
  quadruped); `atk_mid` plants both hind feet (`planted:` overrides, a string or a list). A rearing hurt (wolf, dragon)
  must release the forepaws in `frames: {hurt_in1: {pins: [foot_n, foot_f]}, hurt_in2: {pins: [foot_n, foot_f]}}`,
  otherwise the forelegs hold the chest down.
- Mark the toes: a paw part then rides its pinned ankle without rotating, so it stays on the ground line.
- A pinned foot never moves: when the hip would rise out of the leg's reach, `rig.solve` moves the body toward the
  foot instead of letting the IK lift it.
- A `cloth` part may give its `chain` per keyframe (`chain: {idle: [...], attack: [...]}`); its joints join the wind
  and cast move sets like a plain chain.
- `breath_joint:` moves the `idle_b` cut (default `hip`).
